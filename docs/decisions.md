# 결정 기록

## 페이지를 iframe에 띄워 한 번만 누르게 한다

- **정한 것:** 북마클릿이 현재 페이지 위에 같은 사이트 iframe을 띄우고, 패널과 조작 코드는 바깥 페이지에 둔다.
- **이유:** 필터를 붙이려고 페이지를 새로 열면 북마클릿 코드가 사라져 한 번 더 눌러야 했다. iframe 안에서 페이지가 바뀌어도 바깥 코드는 살아 있어서, 새로 검색해도 패널이 남는다.
- **버린 대안:**
  - 팝업 창 컨트롤러. 창이 하나 더 생기고, 팝업 쪽 코드가 원래 탭의 실행 환경에 묶여 새로 열릴 때 끊길 수 있다.
  - 확장 프로그램. 회사 보안 정책으로 막혀 있다.
- **전제:** 네이버가 `X-Frame-Options`나 CSP `frame-ancestors`를 걸면 이 방식은 막힌다. 그때는 다시 검토한다.

## 필터는 마우스 이벤트를 차례로 보내 누르고, fo=true만 주소로 붙인다

- **정한 것:** 제외와 쿠팡 선택은 예전 확장 프로그램처럼 mouseenter부터 click까지 이벤트를 차례로 보내 화면에서 누른다. `fo=true`는 누를 곳이 없어 주소로 붙인다.
- **이유:** `.click()` 하나만 보내면 네이버 검색 API가 418로 막았다. 파라미터를 바꾼 주소로 페이지를 새로 여는 방식은 동작했지만 캡차가 자주 떴다. 이벤트를 차례로 보내는 방식은 실제 네이버에서 반영됐고 페이지를 새로 열지 않는다.
- **위험:** 실제 마우스 입력처럼 보이게 해서 네이버의 자동화 검사를 넘는 방식이다. 네이버가 검사를 바꾸면 다시 막힐 수 있고, 자동화로 판단되면 계정이나 IP가 제한될 수 있다. 소유자가 이 위험을 알고 정했다. 버튼은 사람이 한 번 누를 때 한 번만 동작한다.
- **버린 대안:**
  - 주소로 새로 열기. 캡차가 자주 떴다.
  - 체크까지만 하고 저장은 사람이 누르기. 클릭이 늘어 작업이 느려진다.

## 북마크에는 로더만 넣고 코드는 원격 main에서 받는다

- **정한 것:** 북마크에는 `loader.js`를 한 줄로 바꾼 로더만 넣는다. 로더는 누를 때마다 `raw.githubusercontent.com`에서 `main`의 `bookmarklet.js`를 받아 `new Function`으로 실행한다.
- **이유:** 코드를 고칠 때마다 팀원이 북마크를 다시 붙여야 했다. 저장소가 공개이고 raw 응답에 `Access-Control-Allow-Origin: *`가 있어 토큰 없이 `fetch`할 수 있다. 네이버에는 CSP가 없어 받은 코드를 실행할 수 있다.
- **위험:** `main`에 푸시할 수 있는 사람은 팀원들의 로그인된 네이버 화면에서 코드를 실행할 수 있다. 그래서 `main` 푸시 권한과 "확인한 코드만 올리기"가 보안 장치다. 코드는 공개 저장소에 그대로 보인다. 네이버가 CSP를 걸거나 회사망이 GitHub raw를 막으면 로더가 동작하지 않는다.
- **캐시:** raw 응답은 `max-age=300`이고, 주소에 쿼리를 붙여도 같은 캐시를 탄다. 그래서 푸시 뒤 반영까지 5분쯤 걸린다.
- **버린 대안:**
  - jsDelivr. `<script src>`로 붙일 수 있지만 브랜치 기준 캐시가 더 길다.
  - GitHub API로 받기. 캐시는 없지만 비인증 요청이 IP당 시간당 60번이라, 같은 회사 IP를 쓰는 팀원이 나눠 쓰면 모자랄 수 있다.
  - 커밋 해시로 고정. 바뀔 때마다 북마크를 다시 붙여야 해서 로더를 쓰는 의미가 없다.
  - 전체 코드 한 줄만 북마크에 넣기. 처음에는 이렇게 했다. 지금은 원격 없이 바로 돌려 볼 때만 쓴다.

## 파이썬 로더를 따로 시험한다

- **정한 것:** 북마클릿은 그대로 두고, Playwright로 디버그 포트를 연 Chrome에 붙어 `py-bookmarklet.js`를 자동으로 넣는 파이썬 로더를 따로 둔다. 시험 중인 방식이다.
- **iframe을 뺀 이유:** iframe은 북마클릿 코드가 페이지 이동 뒤에도 살아 있게 하려고 쓴 것이다. 파이썬 로더는 페이지가 새로 열릴 때마다 코드를 다시 넣으므로 iframe이 필요 없다. 그래서 `bookmarklet.js`를 고치지 않고 `py-bookmarklet.js`를 따로 둔다.
- **이유:** 북마클릿은 네이버가 연 새 탭(예: NPCS)을 잡지 못하고, 회사가 확장 프로그램을 막았다. 파이썬은 회사 PC에서 허용된다. Playwright는 모든 탭에 접근할 수 있어 확장 프로그램처럼 쓸 수 있다.
- **프로필:** Chrome 136부터 기본 프로필에서는 디버그 연결이 막혀 자동화 전용 프로필을 쓴다. 네이버는 그 프로필에서 한 번 로그인한다. 칸반은 기본 프로필에 두고 클립보드로 붙인다.
- **위험:** 디버그 포트가 열린 Chrome은 같은 PC의 어떤 프로그램이든 조종할 수 있다. 그래서 자동화 프로필에는 조직 구글 계정을 로그인하지 않는 편이 안전하다. 봇 탐지와 회사 보안 솔루션에 걸릴 수 있다.
- **버린 대안:**
  - 표준 라이브러리로 CDP 웹소켓을 직접 구현하기. 설치는 필요 없지만 코드가 늘고 기능을 붙이기 번거롭다.
  - Playwright가 직접 Chrome 띄우기. `navigator.webdriver`가 켜져 자동화로 쉽게 보인다.

## 원본과 한 줄 버전을 나눈다

- **정한 것:** 평범한 JS로 쓴 `bookmarklet.js`와 `loader.js`를 의존성 없는 `scripts/build-oneline.js`로 각각 `bookmarklet-oneline.js`와 `loader-oneline.js`로 바꾼다. 주석만 있는 줄을 지우고 나머지 줄은 공백으로 잇는다. `%`는 `%25`, `#`은 `%23`으로 바꾼다. 로더는 한글 같은 비ASCII 문자도 퍼센트 인코딩해 ASCII만 남긴다.
- **이유:** 원본을 그대로 북마크에 붙이면 줄바꿈이 사라지고, `%`는 퍼센트 인코딩으로 풀린다. 로더는 팀원에게 돌리는 파일인데, 한글을 그대로 두면 복사 도구의 인코딩에 따라 깨져 북마크 URL이 망가졌다. 전체 한 줄은 읽을 수 있게 한글을 그대로 둔다.
- **원본 규칙:** 공백으로 이으면 줄 끝 `//` 주석은 뒤 코드를 먹고, 자동 세미콜론은 사라진다. 그래서 `bookmarklet.js`와 `loader.js`에는 줄 끝 주석을 쓰지 않고 문장 끝에 세미콜론을 붙인다. 빌드가 두 경우를 찾아 멈춘다. 단순 검사라 모든 경우를 잡지는 못한다. 로더가 받아 실행할 때는 줄바꿈이 살아 있어 이 규칙이 필요 없지만, 전체 한 줄 버전을 위해 지킨다.
- **버린 대안:**
  - 원본에 `/* */` 주석과 세미콜론, `%` 금지 규칙을 두고 손으로 한 줄로 합치는 방식. 쓰기 불편하고 실수하기 쉽다.
  - 줄바꿈을 `%0A`로 남기는 방식. 원본 제약은 없지만 한 줄 버전에 `%0A`가 수백 개 끼어 읽기 어렵다. 처음에는 이렇게 했다.
  - esbuild나 terser로 압축하는 방식. 의존성이 생기고, 지금 크기에서는 압축할 이유가 적다. 코드가 커져 파일을 나눠야 하면 다시 검토한다.

## 패널은 0.7초마다 맞추되 바뀐 값만 쓴다

- **정한 것:** 네이버가 필터를 누르면 페이지를 새로 열지 않고 화면만 바꾸므로, 패널은 0.7초마다 상태를 읽어 맞춘다. 칸 글자, 버튼 `disabled`, 칩 `data-s`는 값이 다를 때만 쓰고, 탭이 안 보이면 건너뛴다.
- **이유:** 같은 값이라도 매번 쓰면 네이버 페이지 전체의 스타일과 레이아웃을 다시 계산한다. 실제 검색 페이지에서 20초에 29번 재계산했고, 메인 스레드 작업도 초당 7.4ms(패널 없을 때 0.4ms)였다. 바뀐 값만 쓰자 재계산은 0번, 작업은 초당 0.9ms가 됐다.
- **버린 대안:** MutationObserver로 네이버 화면이 바뀔 때만 맞추기. 네이버 페이지는 광고와 추적 때문에 계속 바뀌어 오히려 자주 불릴 수 있고, 코드도 늘어난다.
