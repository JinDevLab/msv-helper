# 결정 기록

## 페이지를 iframe에 띄워 한 번만 누르게 한다

- **정한 것:** 북마클릿이 현재 페이지 위에 같은 사이트 iframe을 띄우고, 패널과 조작 코드는 바깥 페이지에 둔다.
- **이유:** `fo=true`를 붙이려고 페이지를 새로 열면 북마클릿 코드가 사라져 한 번 더 눌러야 했다. iframe 안에서 페이지가 바뀌어도 바깥 코드는 살아 있어서, 새로 검색해도 패널과 `fo=true`가 유지된다.
- **버린 대안:**
  - 팝업 창 컨트롤러. 창이 하나 더 생기고, 팝업 쪽 코드가 원래 탭의 실행 환경에 묶여 새로 열릴 때 끊길 수 있다.
  - 확장 프로그램. 회사 보안 정책으로 막혀 있다.
- **전제:** 네이버가 `X-Frame-Options`나 CSP `frame-ancestors`를 걸면 이 방식은 막힌다. 그때는 다시 검토한다.

## 필터는 클릭 대신 주소로 연다

- **정한 것:** 제외와 쿠팡만 선택은 드롭다운이나 쇼핑몰선택을 누르지 않고, `exagency=true`나 `mall=613264`처럼 파라미터만 바꾼 주소를 iframe에서 새로 연다.
- **이유:** 스크립트 클릭은 실제 마우스 입력이 아니어서 네이버 검색 API가 418로 막았다. 화면의 선택 글자만 바뀌고 결과는 그대로였고, 대기 시간을 늘려도 같았다. 주소로 새로 여는 것은 공유 링크를 여는 일반 페이지 로드라 막히지 않았다.
- **버린 대안:**
  - 클릭 사이 대기 시간 늘리기. 실제 네이버에서 계속 실패했다.
  - 예전 확장 프로그램처럼 mouseenter부터 click까지 이벤트를 차례로 쏘기. 이것도 `isTrusted=false`라서 통과할지 확인하지 않았고, 주소 방식이 먼저 동작했다.

## 원본과 한 줄 버전을 나눈다

- **정한 것:** 평범한 JS로 쓴 `bookmarklet.js`를 의존성 없는 `scripts/build-oneline.js`로 `bookmarklet-oneline.js`로 바꾼다. 줄바꿈은 `%0A`, `%`는 `%25`, `#`은 `%23`으로만 인코딩한다.
- **이유:** 원본을 그대로 북마크에 붙이면 줄바꿈이 사라져 `//` 주석과 자동 세미콜론이 깨지고, `%`는 퍼센트 인코딩으로 풀린다. 원본에 이런 제약을 두는 대신 변환에서 처리한다. 한글은 인코딩하지 않아 한 줄 버전도 읽을 수 있다.
- **버린 대안:**
  - 원본에 `/* */` 주석과 세미콜론, `%` 금지 규칙을 두고 손으로 한 줄로 합치는 방식. 쓰기 불편하고 실수하기 쉽다.
  - esbuild나 terser로 압축하는 방식. 의존성이 생기고, 지금 크기에서는 압축할 이유가 적다. 코드가 커져 파일을 나눠야 하면 다시 검토한다.
