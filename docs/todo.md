# 할 일

- 감지기 몰 번호(이마트 4535661·4531621·4541160, 롯데마트 12317296, 컬리 9080714, 올리브영 197658, 지그재그 9115904, 오늘의집 7696354, 펫프렌즈 1005950)를 원본 명세와 맞춰 본다.

- 실제 네이버에서 이벤트 방식으로 쿠팡 저장이 반영되는지, 적용된 제외 칩을 다시 누르면 풀리는지 확인한다.
- 손으로 쿠팡을 고른 뒤 패널을 열면 전체 수 자리에 쿠팡 수가 들어간다. 이 경우를 막을지 정한다.

## 확인 기록

- 2026-11-11: 쓸데없는 대기를 줄였다. 파이썬 로더는 `load` 대신 `domcontentloaded`에 넣고, 제외는 마지막 항목 뒤에 기다리지 않고, 조건 확인 간격을 0.1초에서 0.03초로 줄였다. 실제 네이버 고무장갑에서 파이썬 로더 방식으로 모두 제외가 3.7초에 끝났다(전에는 4.8초). fo로 새로 연 페이지에서 제외를 시작한 시점이 `complete`(2.3초)에서 `interactive`(1.6초)로 당겨졌고, 해외직구·중고·렌탈이 모두 적용됐다(540,034 → 498,744). 네이버 요소에 `__reactFiber`·`__reactProps`가 붙는 것도 확인했다. 카탈로그 묶어보기 끄기, 숫자가 안 바뀌는 검색어, iframe 버전은 확인하지 못했다.

- 2026-11-06: 제외를 누른 뒤 전체 수가 안 바뀌면 3초씩 기다려 느렸다. 기다림을 1초로 줄였다. 문법 검사와 한 줄 빌드만 했고, 실제 네이버에서 숫자가 그대로인 경우와 응답이 1초보다 늦는 경우는 확인하지 못했다.

- 2026-11-06: 쿠팡이 목록에 없을 때 기다림을 1.5초로 줄이고, 쿠팡 결과 0건이면 쿠팡 칸을 `-` 대신 0으로 보이고 복사하게 했다. 실제 네이버 "올리브유 -쿠팡"에서 쿠팡을 고른 화면(판매처 탭 숫자 없음, `noResult` 안내)에 파이썬 로더 방식으로 넣은 패널이 "올리브유 -쿠팡 / URL / 169,106 / 0"을 보였다. 클립보드 내용, 1.5초 기다림, iframe 버전은 확인하지 못했다.

- 2026-11-04: "웰니스 코어 키튼 900"에서 모두 제외를 누르면 fo 뒤 유사한 상품 화면이 되어 전체 수를 15초 기다리다 말없이 멈췄다. 유사한 상품 안내가 보이고 전체 수가 없으면 바로 "fo 결과 0건"을 띄우게 했다. 실제 네이버에서 파이썬 로더 방식으로 1.2초 만에 안내가 떴고, 고무장갑은 fo, 해외직구, 중고, 렌탈 제외가 차례로 적용됐다(535,159 → 497,563). iframe 버전은 실행해 보지 못했다.

- 2026-11-04: 쿠팡이 쇼핑몰선택 목록에 없을 때 6초 기다린 뒤 레이어를 연 채 끝나 멈춘 것처럼 보였다. 기다림을 합쳐 3초로 줄이고, 레이어를 닫고 쿠팡 수 0으로 복사하게 했다. 11번가만 있는 가짜 레이어에서 3.1초 만에 끝났고, 레이어가 열렸다 닫혔고, 클립보드에 "쿠팡없는검색어 / URL / 1234 / 0"이 들어갔다. 실제 네이버의 쿠팡 없는 검색어와 iframe 버전(`bookmarklet.js`)은 확인하지 못했다.
- 2026-11-04: 작업자들이 점점 느려진다고 해서 실제 네이버에서 쟀다. 검색창 입력 검색 50번(로더 없이 15번, 파이썬 로더를 붙이고 35번) 동안 탭 JS 힙(42~57MB)과 렌더러 메모리는 계속 늘지 않았다. 검색은 매번 페이지를 새로 열어 패널도 다시 들어간다. 파이썬 로더 안의 Playwright 객체는 검색 한 번에 Frame 약 10개, Request·Response 3개씩 늘고 지워지지 않았다(10번에 23 → 183개, 파이썬 메모리 25번에 29 → 32MB). 패널은 같은 값을 0.7초마다 다시 써서 20초에 레이아웃 29번, 초당 7.4ms를 썼고, 바뀐 값만 쓰게 고친 뒤 실제 네이버에서 0번, 0.9ms가 됐다. 주소를 바꾸면 URL 칸이 바로 바뀌었다. 탭이 숨었을 때 멈추는 것과 iframe 버전(`bookmarklet.js`)은 실행해 보지 못했다. 이날 이 PC는 네이버 쇼핑 접속 제한에 한 번 걸렸다.

- 2026-11-04: 파이썬 로더가 iframe 없는 `py-bookmarklet.js`를 넣게 바꾸고, 필터를 누르면 화면만 바꾸는 가짜 페이지로 확인했다. iframe 없이 패널이 떴고, "모두 제외"는 fo를 붙여 페이지를 새로 연 뒤 다시 들어온 코드가 제외 셋을 이어서 눌렀다. 쿠팡 선택 뒤 자동 복사 내용(x / URL / 700 / 270)도 맞았다. NPCS는 `target="_blank" rel="noopener"` 링크, `window.open`, 직접 연 탭 모두 묶어보기가 꺼졌고 패널은 뜨지 않았다. 실제 네이버에서는 확인하지 못했다.

- 2026-11-04: 파이썬 로더를 가짜 페이지와 임시 프로필로 확인했다. 시작할 때 열린 검색 탭, 같은 탭의 새 검색, 새 탭에 패널이 하나씩 들어갔고, 카탈로그 페이지에는 넣지 않았다. 원격 main의 `bookmarklet.js`도 받아졌다. Chrome을 닫으니 로더도 끝났다. 실제 네이버와 자동화 프로필 로그인은 확인하지 못했다.

- 2026-11-04: 감지기를 추가했다. 실제 네이버 탭을 읽기만 해서 상품 카드 셀렉터로 링크 25개가 잡히고 몰 번호가 쿠팡 필터 값(613264)과 같음을 확인했다. 상품 카드를 넣은 가짜 페이지에서 이마트, 컬리 ON과 자동 펼침, 컬리 클릭 시 스크롤과 1.2초 칠하기, 손으로 접기, 모두 OFF일 때 자동 접힘이 동작했다. 몰 번호는 흐린 명세 사진에서 읽은 값이라 원본과 맞춰 보지 못했다.

- 2026-11-04: 로더를 가짜 페이지에서 실행했다. GitHub `main`의 `bookmarklet.js`를 받아 "MSV Helper" 패널과 iframe이 떴고, 한 번 더 눌러도 패널과 iframe은 하나씩이었다. raw 응답은 `max-age=300`이고 쿼리를 붙여도 캐시를 탔다. 실제 네이버, 회사망, 실패 알림은 확인하지 못했다.
